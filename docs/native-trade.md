# 原生交易系统

阅读模式侧边栏和多 Tab 模式的「我的」都可以进入交易系统。原生界面提供我的交易、按买家或卖家身份选择中介创建交易、交易进度、参与邀请链接，以及群聊文字消息和历史加载。

只有「使用 NodeSeek 登录」会打开交易站的官方授权页。授权完成后返回原生界面，App 从 WebKit 会话中读取适用于 `agent-api.nodeseek.org` 的 Cookie，按交易站的会话协议发请求。论坛域的登录 Cookie 不会随交易 API 请求发送。用于公开查询的 `ntk_` Key 不用于私人交易。

论坛与交易系统拥有独立会话。首次授权仍需通过官方 connect，但授权弹窗共用 App 的 WebKit 登录数据，并使用与论坛登录页一致的浏览器标识，无需另建论坛登录态。点击登录前再次检查现有交易会话；原生 API 响应中的会话 Cookie 更新会写回 WebKit，供后续页面和新客户端复用。

一次授权页面只允许发起一次 connect。回到聊天路由后，须由原生 API 确认登录成功才关闭授权页。授权页右上角的「检查登录状态」只检查已有交易会话，不发起 connect。若官方提示授权次数已达上限，客户端不能通过论坛 Cookie 绕过限制，也不会自动重试授权；需要等待官方限制解除。

交易列表支持标题、最近消息和编号搜索，以及进行中、已结束和未读筛选，展示交易阶段、当前身份、未读数和最后更新时间。中介列表加载失败不会阻止查看已有交易。通过官方邀请链接可预览条款，选择服务端允许且未被占用的身份加入；已有身份直接打开交易，旁观邀请以只读身份加入。

详情展示人民币金额、中介费、费用承担方、交货方式、参与者与完整进度。草稿阶段可以编辑标题、价格、费用和关联帖子，保留品牌及交货方式等未编辑字段。敲定、确认／退回条款、同意／拒绝解锁和交易进度操作只向当前角色展示。所有写入二次确认，并在提交前重读交易；版本、条款、参与者或权限变化时要求重新核对。积分红包交易暂只读进度，未接入资金划转操作。

聊天支持多行输入、回复、复制、已加载消息搜索、历史分页和回到最新消息。每条消息显示区域化日期及毫秒时间。仅在页面可见且 App 在前台时轮询；只同步已显示消息的已读状态，失败不阻塞发送并可重试。

创建、加入、交易操作和消息发送在网络结果不明时不会自动重试。消息保留草稿及回复对象；交易操作结果不明时须刷新核对后手动解锁操作。附件、托管大厅、积分红包划转及三方重置申请处理尚未接入。

接口验证使用未登录请求和虚构数据：正常会话签名后可读取登录配置，未登录请求私人交易数据仍会收到 401。没有在真实账户中创建交易或发送消息。
