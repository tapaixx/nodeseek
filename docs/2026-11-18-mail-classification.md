# 邮件分类标志展示

## 已确认的问题

列表接口包含 `tags` 字段，详情接口另有 `data.tags`，旧模型和界面未完整保留、展示这些标签。文件夹归属虽以 `folderId` 保存，邮件行与详情也未说明所属文件夹。

本次将标签名称和分类颜色显示到邮件列表、详情，提供标签筛选，并保留文件夹归属。颜色仅用于图标，文字使用系统动态色；未知颜色回退系统色，名称始终保留。

## 接口与范围

- 读取 `GET /tags` 作为标签目录，权限为 `tag:read`；权限不足不会阻塞收件箱，列表或详情内返回的标签仍可展示。
- 标签筛选使用现有 `GET /mails?tag_id=...`，可同时叠加邮箱、文件夹和搜索条件。筛选范围的缓存相互隔离。
- 目录使用短期内存缓存，标签及邮件分类信息也写入原有按 Key 指纹隔离的快照。缺失或为 null 的旧字段继续按空集合解码。
- 仅展示和筛选，不创建、修改、删除真实标签、邮件或已读状态。

## 邮箱分组的未解决项

“邮箱的分组”和“邮件所在文件夹”是两种不同的数据。本次只读核验中，`GET /mailboxes` 的所有对象均不含 group、tag、label 相关字段；`/openapi/v1/groups`、`/openapi/v1/mailbox-groups` 返回 404，公开站点文档页面返回 468。

因此本次没有接入或宣称同步网站独立的邮箱分组，也没有用“最近使用／未读”等应用内分类替代网站分组。独立邮箱分组仍需确认可用的接口或数据来源。

验证只记录字段结构和 HTTP 状态，不保存临时 Key、真实地址及邮件内容。界面及写操作回归使用虚构数据。
